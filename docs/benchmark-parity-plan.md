## 2026-10-11 모바일 요구 개정

최신 제품 요구는 모바일 전용·전투 이동 방향키만 입력·나머지 실시간 판단 자동화·전투 후 재화 재설정과 자유 커스텀이다. 구현 명세는 [모바일 자동화 설계](mobile-autopilot-design.md)를 우선한다. 아래 원작 대응표는 콘텐츠 조사 기준으로 유지하되 수동 선택과 입력 동일성은 완료 조건에서 제외한다. 전투 자동화는 보류 항목에서 필수 P0 작업으로 변경한다. 현재 배포 게임에 자동화가 구현됐다는 뜻은 아니다.

## 결론

현재 게임은 원작을 참고한 모바일 웹 프로토타입이다. 이동 → 자동 전투 → 레벨업 선택 → 보상 → 장비 → 재도전의 연결은 구현했지만, 동일한 게임으로 평가할 근거는 부족하다. 지금 필요한 것은 작은 UI 기능 추가보다 기준 버전 확정, 관찰 가능한 명세, 데이터·에셋 제작, 대표 구간 검증이다.

완료율을 임의의 퍼센트로 표시하지 않는다. 원작의 전체 항목 목록과 수치가 아직 없기 때문이다. 엔진 테스트 15개 통과는 현재 코드의 일부 규칙 검증이며 원작 동일성·모바일 성능의 증거가 아니다.

## 1. ‘동일하게 구현’의 세 범위

| 범위 | 완료 의미 | 추가로 필요한 것 |
| --- | --- | --- |
| 시스템 동일성 | 전투·성장·장비·해금 규칙이 기준 버전과 대응 | 수치·규칙·전체 콘텐츠 목록과 비교 시나리오 |
| 시청각 동일성 | 화면 구도·캐릭터·애니메이션·이펙트·음악까지 대응 | 사용할 수 있는 원작 에셋·원본 자료 및 사용 범위 확인 |
| 모바일 제품 동일성 | 위 체험을 터치·중단·설치 환경에서 안정적으로 제공 | 실기기 QA, 성능 예산, 저장 복구, 모바일 배포 형식 |

권장 방향: 시스템과 콘텐츠의 대응을 먼저 확보하고 터치 UI를 별도로 최적화한다. 모바일 때문에 전투 시간을 임의로 줄이거나 빌드 선택을 삭제하면 동일성 목표에서 벗어난다. 원작 에셋을 사용할 수 없다면 독립 아트로 진행하되 시청각 완전 동일성은 목표에서 구분한다.

## 2. 근거와 아직 모르는 것

- [S1] Steam 공식 소개: 루팅 RPG, 수백 아이템, 무작위 옵션, 로비 장착·강화, 장비에 따른 외형 변화, 손으로 그린 2D 다크 판타지를 설명한다.
- [P1] 2025-07-04 1.5.0 개발자 공지의 SteamDB 보존 본문: 축복 성장 공유, 계정 공통 층 진행, 3단계 난이도, 혼돈 던전 보상 조정 등을 설명한다. 과거 버전의 근거이며 현재 전체 규격은 아니다.
- [P2] 2025-06-27 1.4.0 보존 공지: 연금술 NPC, 보석·주얼·룬 변환, 장비 프리셋 3개, 큰 글씨와 피해 숫자 설정 등을 설명한다. 현재 동작은 별도 검증해야 한다.
- [R1] 2026-06 리뷰는 직업별 트리, 소켓·장비 조합, 혼돈 던전의 깊이를 평가한다. 직업 수 등은 리뷰 설명으로만 분류하고 최신 공식 목록으로 확정하지 않는다.
- [V1] 기존 데모 소개 영상은 다시 직접 열기를 시도했으나 가져오기 실패. 전체 재생 화면·자막·정확한 타이밍을 이번에도 확보하지 못했다.

원작의 정확한 층 수, 직업 목록, 스킬 상한·진화 조건, 장비 부위·옵션 풀, 공격·피해 공식, 드롭 확률, 전투 길이, 패배 손실, 보스 패턴, 현재 패치 버전은 확정되지 않았다. 추정값을 원작 값으로 채우지 않는다. 데모·앞서 해보기·정식 버전의 규칙을 한 명세에 섞지 않는다.

## 3. 현재 구현과 차이

| 영역 | 현재 코드 | 동일성 목표에 필요한 작업 | 우선순위 |
| --- | --- | --- | --- |
| 전투 시간 | 90초 일반전 + 60초 보스 제한 | 기준 영상의 구간·웨이브·보스 조건을 측정해 교체 | P0 |
| 직업 | 독립 설계 3종, 기본 공격만 주요 차이 | 실제 직업별 전용 능력·트리·해금·장비 제한 조사 | P1 |
| 스킬 | 모든 직업 공통 9종, 단순 레벨 강화 | 실제 후보 풀·레벨·시너지·축복·영구 성장 구분 | P1 |
| 장비 | 3부위, 5등급, 부위별 단일 수치 | 실제 아이템 정의·다중 옵션·고유 효과·소켓·재료 규칙 | P1 |
| 장비 외형 | 장착에 따른 그래픽 변화 없음 | 부위별 합성 레이어·방향·애니메이션 동기화 | P1 |
| 강화 | 공격·체력·보상 3종 공통 강화 | 원작의 축복·장비 강화·자원 체계를 구분 구현 | P1 |
| 맵 | 같은 1600×1600 공간, 색상과 이름 변경 | 층별 지형·장애물·충돌·동선·출현 조건 조사 | P1 |

| 허브 | 버튼과 모달 중심 로비 | 원작 NPC·시설·상호작용·해금 조건과 대응 | P2 |
| 난이도·엔드게임 | 5층만, 선택 난이도와 혼돈 던전 없음 | 기준 버전의 난이도·보상·반복 성장 구현 | P2 |
| 아트·음향 | Canvas 도형, 합성 효과음 | 캐릭터·적·환경·UI·애니메이션·BGM 제작 계획 | P1 |
| 모바일 품질 | 저장·회전 대응·왼손 모드 존재 | 실기기 터치·안전 영역·가림·온도·FPS 검증 | P0 |
| 저장 | localStorage, 기기 간 공유 없음 | 저장 스키마·이전 버전 이관·백업·손상 복구 | P1 |

등급 개수나 부위 개수가 같아 보인다는 이유로 대응 완료 처리하지 않는다. 현재 이름·수치·직업은 독립 설계다.

## 4. 먼저 확보할 자료

1. 기준 빌드 식별: 버전, 날짜, DLC 포함 여부, 화면 비율, 설정, 언어.
2. 같은 버전의 첫 층 전체 플레이: 로비 → 선택 → 첫 경험치 → 모든 레벨업 → 보스 → 결과 → 장비 장착 → 재도전.
3. 중간·후반 층과 각 직업 플레이, 희귀 장비·소켓·강화·NPC·혼돈 던전 화면.
4. 텍스트가 읽히는 장비·스킬·능력치·설정 스크린샷. 번역명이 달라도 내부 식별자는 일관되게 관리.
5. 가능한 원본 데이터·에셋 명세와 사용 가능 범위. 없으면 관찰로 확정할 수 있는 규칙부터 구현.
6. iPhone Safari / Android Chrome 실기기 테스트 결과. 설치·복귀·오프라인 상황 포함.

각 관찰은 ‘자료 URL / 버전 / 타임코드 / 관찰 / 수치 / 신뢰도 / 구현 항목 / 검증 상태’를 함께 기록한다. 영상 설명·챕터는 조사 위치의 단서이며 직접 관찰로 승격하지 않는다. 정보가 없는 항목은 미확정으로 남긴다.

## 5. 개발 구조 검토

지금 즉시 엔진 전체를 교체할 근거는 없다. 첫 대응 구간을 현재 Canvas에서 만든 뒤 대표 전투의 성능을 측정한다.

- 콘텐츠 정의를 코드에서 분리: classes, skills, items, affixes, enemies, floors, waves, lootTables, progression, localization.
- 장비 모델은 기본 아이템 + 등급 + 옵션 + 고유 효과 + 소켓 + 강화 단계로 확장. 순서는 실제 규칙 확인 후 결정.
- 피해·공격 속도·치명타·관통·범위·상태 효과에 적용 순서와 중첩 정책을 정의. 동일한 효과가 중복 반영되지 않도록 한다.
- 시뮬레이션 시간과 렌더링을 분리하고 고정 시간 간격·시드 난수·이벤트 기록을 검토. 프레임 속도에 따라 출현과 보상이 달라지지 않아야 한다.
- 렌더링은 바닥 좌표와 화면 투영을 구분하고 깊이 정렬·장애물 충돌·방향별 애니메이션을 지원.
- 저장 버전 이관, 신규 아이템 식별자, 기존 장비 보존, 실패 시 복구 경로를 콘텐츠 확대보다 먼저 준비.
- 대표 장면의 객체 수·픽셀 수·효과 중첩을 측정. Canvas 유지, WebGL 전환, 엔진 전환은 이 측정 뒤에 결정.

코드 검토 중 발견한 추가 점검 항목: 정예 출현이 시간의 정수 구간 판정에 연결되어 있어 같은 1초 안에 복수 출현할 가능성이 있다. 저장 복원 검사는 위치·일부 배열을 확인하지만 모든 수치·하위 구조·설정 타입을 포괄하지 않는다. 이 문서에서는 수정하지 않았으며 기반 안정화 작업에 포함한다.

## 6. 실행 순서와 통과 조건

| 단계 | 결과물 | 통과 조건 |
| --- | --- | --- |
| A. 기준 고정 | 버전·범위·기능 대응표·미확정 목록 | 대상 버전이 하나이고 각 요구에 출처 또는 미확정 표시가 있음 |
| B. 첫 층 대응 | 1직업·1층·보스·결과·장비·재도전 | 동일 구간의 화면·규칙·타이밍 비교와 터치 완료가 가능 |
| C. 핵심 깊이 | 스킬·옵션·고유 효과·성장·저장 이관 | 서로 다른 빌드가 실제 행동 차이를 만들고 효과 공식 검증이 통과 |
| D. 표현 대응 | 허브·장비 외형·캐릭터·적·음향 | 대표 장면의 구도·가독성·외형 변화를 비교 검토 |
| E. 콘텐츠 확대 | 확정된 직업·층·보스·난이도·후반 모드 | 미구현 필수 항목이 없고 해금·반복 성장 흐름이 끊기지 않음 |
| F. 모바일 제품 검증 | 기기별 QA·성능·설치·복구 기록 | 장시간 전투·중단·저장 이관·오프라인 테스트 통과 |

전투 시간·레벨업·드롭·효과 수치의 허용 차이는 기준 측정 후 설정한다. 다음은 원작 측정값이 아니라 모바일 검증 목표의 초안이다: 조작 영역 44 CSS px 이상, 360px 세로 화면에서 중요 텍스트 읽기 가능, 목표 60FPS 및 대표 최대 부하에서 지속 30FPS 이상, 20분 플레이 후 복귀·저장 안정성 확인. 평균 FPS만 보지 않고 느린 프레임·발열·메모리 증가를 함께 기록한다.

| 실제 사용자 전투 기록·실패 원인 요약 | 난도·선택·조작 문제를 분리 | 먼저 로컬 계측, 외부 수집은 별도 범위 |
| 이동 외 전투 판단 자동화·전투 후 커스텀 | 최신 사용자 지정 모바일 요구 | 필수 P0, mobile-autopilot-design.md에 따라 구현 |
| 광고·과금·협동·서버 계정 | 신규 제품 방향 확장 | 현재 범위에서는 보류 |
| 처음부터 네이티브 엔진으로 전면 재작성 | 패키징·그래픽 확장 가능성 | 성능 병목과 아트 파이프라인 확인 전 보류 |

## 8. 작업 목록과 우선순위

P0: 이동 전용 D-pad·자동 스킬 선택·자동 회피/폭발 / 자동화 설정·판단 기록 / 기준 버전 고정 / 영상·스크린샷 관찰표 / 실기기 기본 QA / 전투 시간·웨이브 규칙 / 대표 장면 성능 측정.

P1: 데이터 구조 분리 / 저장 이관 / 전투 공식·상태 효과 / 정예 일정 / 한 직업 전용 트리 / 다중 장비 옵션·고유 효과 / 장비 외형 / 한 층 지형·보스 / 효과 가독성 설정.

P2: 전체 직업·층 데이터 / 허브·NPC / 프리셋·강화·소켓 / 난이도·후반 던전 / 음향과 애니메이션 완성 / 설치·배포 형식 확정.

각 작업 카드는 출처, 의존 작업, 수용 조건, 검증 자료를 포함한다. 작업량은 데이터와 애니메이션의 개수가 확정된 뒤 산정한다. 현재 정보만으로 전체 기간·비용·완료율을 신뢰할 수준으로 계산할 수 없다.

## 9. ‘끝날 때까지 진행’의 운영 규칙

한 회차마다 하나의 필수 차이를 해결하고 비교 증거를 남긴다. 보고는 ‘무엇이 달라졌는가 / 기준 자료 / 검사 / 남은 차이’ 형식을 유지한다. 빌드 시각은 버전 확인 수단이며 완료 증거는 아니다. 새로운 UI 개선만으로 대응 작업을 대체하지 않는다.

미확정 규칙은 임의 구현해 완료 처리하지 않는다. 해당 항목은 자료 대기 상태로 두고 독립 작업을 진행한다. 수용 조건을 통과한 첫 구간을 본보기로 전체 콘텐츠를 확대한다. 현재의 완주 테스트에 장비 효과·상태 중첩·웨이브·저장 이관·반복 파밍 검증을 추가한다.

최종 종료 조건: 필수 항목 전수 대응, 미확정 핵심 규칙 해소, 대표 장면 비교 검토, 실기기 QA, 지속 성능·저장 복구 검증. 남은 예외는 별도 승인된 모바일 변경점으로 문서화한다.

이 문서의 초기 비교표 이후 이동 전용 입력, 자동 선택·회피·필살기, 유료 옵션 편집 및 되돌리기, 클래스별 3개 프리셋, 자동 강화 예산, 거래 중복 방지, 저장 복구와 설정 하단 빌드 시간이 구현됐다. 상세 목록은 `mobile-autopilot-design.md`를 따른다.
